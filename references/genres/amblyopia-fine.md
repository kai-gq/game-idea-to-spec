# 弱视精细训练（透明背景）

> 与红蓝训练（`amblyopia-redblue.md`）并列的第二条路线。
> **玩法、素材、工程纪律全部照常规游戏**（公共流水线照旧；本文不另设玩法 / 素材条款）；
> 与常规的**唯一差异 = 背景全透明**：**背景层不画**（整幅底 / 大面都不画）——背景不是画的
> 内容，是留给后期叠加的物理光栅的透光层；整块不透明面会把它盖住（冒烟会用代码查，见 §2）。
> **场景里的元素（月亮、星星、太阳、飞机这类主题 / 装饰对象）不受这条限制**，照常规游戏画。
> 本文是生成规范，不是医学建议。

流程照旧（读 skill → `set_plan` → TASK.md 清单驱动 → 冒烟交付）；本文只写这一处差异。

## 1. 透明背景纪律（唯一差异）

这一类游戏的"背景"不画——它是**给物理光栅留的透光层**。三条：

1. **Phaser config 里的 `transparent` / `backgroundColor` 两键必须这样写（一字不差）**：

```js
// 游戏启动处的 Phaser config（new Phaser.Game({...})）
const config = {
  type: Phaser.AUTO,
  width: W, height: H,
  transparent: true,                 // ★ 此键同时是冒烟「透明校验」的触发信号——写法必须一字不差
  backgroundColor: 'rgba(0,0,0,0)',  // ★ 照抄这个写法（不是 '#000'、不是 0x000000）
  scale: { mode: Phaser.Scale.RESIZE },   // 族 1（单屏）默认；缩放口径见 file-protocol.md §4(c)
  scene: [Boot, Play],
};
```

   触发口径：冒烟扫 `game/` 源码（`.html` / `.js` / `.mjs`，**排除 `lib/`**）里出现
   `transparent: true` → 这局按"透明类"跑（判据与红点读法见 §2）。写了这键但背景画实心 =
   判红正确（要么改码、要么改画法）；漏了这键而背景画实心 = 没人替你查、光栅被盖住——交付事故。

2. **页面壳**：html/body 背景 transparent、画布 CSS 无背景：

```css
html, body { margin: 0; height: 100%; overflow: hidden; background: transparent; }
canvas { touch-action: none; }   /* 只留 touch-action；不给画布设 background */
```

3. **背景层什么都不画**：整幅底 / 铺满的大面（纯色 / 渐变 / 风景底、底图、实心大面板）
   都不画——光栅就是背景。**场景里的元素（月亮、星星、太阳、飞机这类主题 / 装饰对象）
   不受本条限制**；玩法对象、HUD、界面等其余一切**照常规游戏**；透明校验自动兜底
   （兜的就是背景 / 大面板这类整块事故），被拦了按 §2 的修法处理。

## 2. 冒烟与透明校验（怎么读，红了怎么改）

**触发（自动，零配置）**：冒烟扫 `game/` 源码（`.html` / `.js` / `.mjs`，**排除 `lib/`**）
里出现 `transparent: true` → 这局按"透明类"跑：窗口切透明、截图整程走 `capturePage`
（这样截出来的图**保留 alpha**；键盘 / 鼠标注入不受影响，steps 与乱点电池照常），
收尾自动跑**透明校验**——纯静态画面分析，不需要交互，invariants light 模式也跑。

**判据（初值）**：

| 指标 | 绿 | 警告（注记，不判红） | 红 |
|---|---|---|---|
| 最大不透明连通块占比 | <10% | 10–15% | **>15%** |
| 不透明像素总占比 | <35% | 35–50% | **>50%** |

阈值兜的是"把背景 / 大面板画上了"这类事故。**红点长这样**（进 `reasons`；`[前缀]` 会被
自动修复令回灌给 maker）：

```
[透明] 最大不透明连通块占 34.2%（阈值 15%）——整块背景会遮挡光栅；背景走 transparent:true，元素保留
```

**红了怎么改**（照第一条修，别没看懂就重跑）：

1. 背景改回 `transparent: true` + `backgroundColor: 'rgba(0,0,0,0)'`（§1 第 1 条），
   壳 html/body 也清掉背景（§1 第 2 条）；
2. 删背景层与整块不透明大面：纯色 / 渐变 / 风景底、铺满的纹理、实心大面板（主题 / 装饰小元素不算）；
3. 改完**停手**——主程序自动复冒烟，别自己手跑抢自动回路（口径同 `verification.md` §7）。
**看截图注意**：透明模式下 `Read` 到的截图**背景是全透明的**（不是白底）——这是正常的，
重点看内容（对象、界面）。

## 3. 工程差异清单

在常规工程纪律之上，精细类只加两条：

1. **玩法说明.txt 追加**（交付形态的一部分）：
   - "本游戏背景是**透明**的：请按医嘱 / 训练要求把光栅片叠在屏幕前（叠加后期手动做，
     游戏里不显示光栅）；"
   - 建议视距 ≈60cm、屏幕高度与视线平齐；
   - 单次训练建议 15~20 分钟（用"再来一局"多轮）；
   - "请遵医嘱 / 在治疗师指导下使用。"
2. **收尾冒烟照旧 ＋ 透明校验自动跑**（§2）。
